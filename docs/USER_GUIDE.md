# คู่มือลองเล่น LeadLoop

## ลองเล่นเฉพาะหน้าเว็บ (ไม่ต้องติดตั้งอะไร)

ใช้เมื่อมีคนเปิดระบบไว้ให้แล้ว (เช่น ผู้พัฒนาเปิดไว้ในเครื่องหรือส่งลิงก์ชั่วคราวมาให้)
ข้อมูลทั้งหมดเป็นข้อมูลทดสอบ ใช้ชื่อสมมติเท่านั้น

1. เปิดลิงก์ที่ได้รับ แล้วล็อกอินด้วยบัญชีที่ผู้พัฒนาแจ้ง
2. **ดูโพสต์ที่รออนุมัติ**: เมนู "อนุมัติคอนเทนต์" → กดอนุมัติ (ต้องเป็นคนละบัญชีกับผู้สร้าง)
3. **ลองเป็นลูกค้า**: เปิดลิงก์ `.../chat?c=<เลขแคมเปญ>` ในแท็บใหม่ (หรือในมือถือ) กดยินยอม แล้วพิมพ์ เช่น "ราคาเท่าไหร่" "ผ่อนได้ไหม" "ขอคุยกับเจ้าหน้าที่"
4. **ดูลีด**: กลับมาที่เมนู "ลีด" จะเห็นลูกค้าที่เพิ่งคุย พร้อมคะแนนและเหตุผล คะแนนถึง 50 จะเป็น Hot
5. **ปิดการขาย**: เปิดลีด Hot แล้วกด "ปิดการขายได้" หรือ "ไม่สำเร็จ"
6. **ดูผล**: เมนู "รายงาน" และ "ติดตามลีด" (ร่างข้อความติดตามที่รอคนอนุมัติ)

ข้อจำกัดตอนนี้: เชื่อม LINE Official Account ทดลองแล้ว (ลูกค้ากดยินยอม ถามราคา ขอคุยเจ้าหน้าที่ และถอนความยินยอมได้) และเซลส์ตอบลูกค้าจากหน้าลีดได้ทั้งแชตหน้าเว็บและ LINE

ส่วนที่เหลือของเอกสารนี้สำหรับคนที่ต้องการติดตั้งเองบนเครื่องตัวเอง

# ติดตั้งเองตั้งแต่เริ่มต้น

คู่มือนี้พาติดตั้งและลองใช้ LeadLoop บนเครื่องตัวเอง ใช้เวลาราว 15 นาที
ข้อมูลทุกอย่างเป็น **ข้อมูลทดสอบ** ห้ามใส่ข้อมูลลูกค้าจริงจนกว่า PDPA จะได้รับอนุมัติ

## 1. สิ่งที่ต้องมี

- Docker Desktop (เปิดแล้ว ไอคอนเป็นสีเขียว)
- Node.js 18 ขึ้นไป
- Git และ PowerShell (Windows)

## 2. ดึงโค้ดและตั้งค่า

```powershell
git clone https://github.com/rubyjenner/lead-loop.git
cd lead-loop
Copy-Item .env.example .env
```

เปิดไฟล์ `.env` แล้วแก้ค่าเหล่านี้ (ใช้ได้เฉพาะลองบนเครื่องตัวเอง ห้ามใช้กับระบบจริง)

```dotenv
POSTGRES_PASSWORD=change-me-local-only
JWT_SECRET=local-test-secret-at-least-32-characters-long
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=Admin123!
PUBLIC_CHAT_ENABLED=1
```

- `ADMIN_EMAIL` / `ADMIN_PASSWORD` คือบัญชีแอดมินคนแรก ระบบสร้างให้ตอนเริ่มครั้งแรก
- `PUBLIC_CHAT_ENABLED=1` เปิดหน้าแชตลูกค้า (ถ้าไม่ตั้ง หน้า `/chat` จะแสดงว่าปิดอยู่)
- ช่อง `ANTHROPIC_API_KEY` และ `GEMINI_API_KEY` เว้นว่างได้ ระบบจะใช้เทมเพลตแทน AI
- ห้ามนำไฟล์ `.env` เข้า git

## 3. เริ่มระบบ

```powershell
docker compose up -d --build
```

รอราว 1-2 นาที แล้วเช็กว่าระบบพร้อม

```powershell
curl.exe http://localhost:8080/health
```

ต้องได้ผลลัพธ์ว่า ok จากนั้นเปิดหน้าเว็บ (หน้าต่าง PowerShell ใหม่)

```powershell
cd frontend
npm install
npm run dev
```

เปิดเบราว์เซอร์ไปที่ **http://localhost:5173**

## 4. ใส่ข้อมูลตัวอย่าง (ไม่บังคับ)

ถ้าอยากได้ข้อมูลเดโมพร้อมใช้ทันที ให้รันในหน้าต่างใหม่

```powershell
$env:SMOKE_ADMIN_PASSWORD = 'Admin123!'
.\scripts\demo-seed.ps1
```

ถ้าขึ้นเรื่อง ExecutionPolicy ให้รัน `Set-ExecutionPolicy -Scope Process Bypass` ก่อน

## 5. ล็อกอินและลองใช้ตามขั้นตอน

ล็อกอินที่ http://localhost:5173 ด้วย `admin@example.com` / `Admin123!`

### 5.1 สร้างบัญชีเซลส์และการตลาด
เมนู **ผู้ใช้** → เพิ่มผู้ใช้ เลือกบทบาท `marketing` หรือ `sales` ระบบจะให้ลิงก์เชิญ ให้เปิดลิงก์ในหน้าต่าง Incognito เพื่อตั้งรหัสผ่านของบัญชีนั้น

| บทบาท | ทำอะไรได้ |
|---|---|
| admin | ทุกอย่าง รวมจัดการผู้ใช้และรันงานรายวัน |
| marketing | สร้างแคมเปญ โพสต์ อนุมัติโพสต์และข้อความติดตาม |
| sales | ดูลีด รับลีดที่ส่งต่อ ปิดการขาย |

### 5.2 สร้างโพสต์และให้คนอื่นอนุมัติ
1. เมนู **แคมเปญ** → เพิ่มสินค้า (ใส่ชื่อ ราคา ลิงก์รูป) แล้วสร้างแคมเปญ
2. เปิดแคมเปญ กดให้ AI ร่างโพสต์ แล้วกด **ส่งขออนุมัติ**
3. ลองอนุมัติด้วยบัญชีเดียวกับผู้สร้าง ระบบจะ **ปฏิเสธ** (กฎบริษัท: ผู้อนุมัติต้องเป็นคนละคน)
4. ล็อกอินอีกบัญชี (admin หรือ marketing) เมนู **อนุมัติคอนเทนต์** → อนุมัติ

### 5.3 ลองเป็นลูกค้า
เปิด `http://localhost:5173/chat?c=<เลขแคมเปญ>` (เลขแคมเปญดูได้จากหน้าแคมเปญ)

1. จะเห็นรูป ราคา และโพสต์ที่อนุมัติแล้วเท่านั้น
2. พิมพ์ข้อความ ระบบขอความยินยอมก่อน (ถ้ากด "ไม่ยินยอม" จะไม่มีลีดเกิดขึ้น)
3. กดยินยอม ใช้ชื่อสมมติ แล้วลองพิมพ์ เช่น "ราคาเท่าไหร่" "ผ่อนได้ไหม" "ขอคุยกับเจ้าหน้าที่"
4. กด "ถอนความยินยอมและหยุดคุย" เมื่ออยากหยุด

### 5.4 ดูลีดและคะแนน
เมนู **ลีด** จะเห็นลีดใหม่ช่อง web เปิดดูแล้วจะเห็นคะแนนและเหตุผลทีละข้อ
เมนู **กฎคะแนน** แก้คะแนนของแต่ละกฎได้ คะแนนถึงเกณฑ์ (ค่าเริ่มต้น 50) ลีดจะเป็น Hot และส่งต่อเซลส์

### 5.5 เซลส์รับลีดและปิดการขาย
ล็อกอินบัญชีเซลส์ เมนู **ลีด** จะมีป้ายตัวเลขแจ้งว่ามีลีดพร้อมส่งต่อ เปิดลีด กดรับ แล้วกด **ปิดการขายได้** หรือ **ไม่สำเร็จ**
ตอบลูกค้า: ในหน้ารายละเอียดลีดของลูกค้าจากแชตหน้าเว็บหรือ LINE มีกล่อง "ตอบลูกค้า" พิมพ์ข้อความแล้วกด "ส่งถึงลูกค้า" ข้อความจะขึ้นในหน้าแชตของลูกค้าภายในราว 5 วินาที (ลูกค้าต้องเปิดหน้าแชตอยู่และยังไม่ถอนความยินยอม) ส่วนลีด LINE ข้อความจะเข้า LINE ของลูกค้าทันที

แชตต่อเนื่อง: เมื่อลีดเป็น "พร้อมส่งต่อ" หรือ "ส่งต่อเซลส์แล้ว" บอทจะหยุดตอบ ข้อความที่ลูกค้าพิมพ์ต่อจะขึ้นในบทสนทนาของหน้าลีด (หน้านี้อัปเดตเองทุก 5 วินาที) และมีป้าย "ข้อความใหม่" ในรายการลีดกับเมนูลีด เซลส์ตอบต่อได้เรื่อย ๆ จนกด "ปิดการขายได้" หรือ "ไม่สำเร็จ" ข้อความที่เก็บไว้จะถูกลบเมื่อลูกค้าถอนความยินยอม

ข้อมูลสินค้าที่บอตใช้ตอบลูกค้า: ในเมนู "แคมเปญ" มีตาราง "สินค้าและข้อมูลที่บอตตอบลูกค้าได้" ปุ่ม "แก้ไขสินค้า" ให้การตลาดแก้ชื่อ ราคา รายละเอียด และกรอก รุ่น/ขนาด/สี, แบบสินค้า, บริการหลังการขาย, ชำระเงินได้ด้วยอะไร และผ่อนได้ไหม (รวมกับราคาเป็นข้อมูล 6 ช่อง) บอตตอบลูกค้าจากข้อความที่กรอกตรง ๆ ช่องไหนว่าง บอตจะส่งคำถามนั้นให้เจ้าหน้าที่ตอบ ไม่เดาเอง และเมื่อลูกค้าพิมพ์ว่าพร้อมซื้อ (เช่น "เอาเลย" "สั่งซื้อยังไง") บอตสรุปราคากับช่องทางชำระเงินที่มีในระบบ แล้วส่งต่อให้เจ้าหน้าที่ยืนยันการสั่งซื้อ (ลีดเป็น "พร้อมส่งต่อ" ทันที) การกด "ปิดการขายได้" ยังเป็นของเจ้าหน้าที่

รูปสินค้า: ตอนเพิ่มสินค้าในเมนู "แคมเปญ" อัปโหลดรูป (png, jpeg, webp) ได้ ระบบย่อรูปให้อัตโนมัติก่อนส่ง รูปจะขึ้นหน้าร้านของลูกค้า และจะถูกส่งให้ AI (Claude หรือ Gemini) ตอนที่คุณสั่งให้ AI วางแผนแคมเปญหรือร่างคอนเทนต์ AI ใช้รูปบรรยายสิ่งที่มองเห็นเท่านั้น ไม่เดาสเปกหรือราคา ในหน้าแคมเปญมีช่อง "แนบรูปเฉพาะครั้งนี้" ถ้าอยากให้ AI ดูรูปอื่นโดยไม่บันทึก ห้ามใช้รูปที่มีใบหน้าหรือข้อมูลส่วนบุคคลของใคร

### 5.6 งานรายวันและข้อความติดตาม
ระบบตรวจลีดที่เงียบทุกวัน 09:00 แล้วร่างข้อความติดตามให้ ถ้าอยากลองทันที ให้แอดมินเรียก
`POST /daily-jobs/run` (หรือรัน `.\scripts\daily-smoke-test.ps1`) แล้วเปิดเมนู **ติดตามลีด** เพื่ออนุมัติร่างข้อความ

### 5.7 รายงาน
เมนู **รายงาน** แสดงจำนวนลีดแยกตามช่องทาง แคมเปญ ช่วงคะแนน และผลปิดการขาย

## 6. รันชุดทดสอบ (ไม่บังคับ)

```powershell
$env:SMOKE_ADMIN_PASSWORD = 'Admin123!'
.\scripts\leads-smoke-test.ps1
.\scripts\daily-smoke-test.ps1
.\scripts\public-chat-smoke-test.ps1
```

ทุกชุดควรจบด้วย `0 failed` ใช้กับฐานข้อมูลทดลองเท่านั้น

## 7. หยุดและล้างข้อมูล

```powershell
docker compose down        # หยุดระบบ เก็บข้อมูลไว้
docker compose down -v     # หยุดและลบข้อมูลทั้งหมด (เริ่มใหม่หมด)
```

## 8. แก้ปัญหาเบื้องต้น

| อาการ | วิธีแก้ |
|---|---|
| ล็อกอินแล้วขึ้น 429 | ล็อกอินผิดหลายครั้ง รัน `docker compose restart api` |
| แก้ `.env` แล้วไม่มีผล | รัน `docker compose up -d --force-recreate api` |
| เปิด `/chat` แล้วขึ้น "แชตนี้ปิดอยู่" | ตั้ง `PUBLIC_CHAT_ENABLED=1` ใน `.env` แล้ว recreate ตามข้างบน |
| `npm run dev` ไม่ขึ้นหน้าเว็บ | ตรวจว่าอยู่ในโฟลเดอร์ `frontend` และรัน `npm install` แล้ว |
| รันสคริปต์ `.ps1` ไม่ได้ | `Set-ExecutionPolicy -Scope Process Bypass` ในหน้าต่างนั้น |
| `curl` ใน PowerShell แปลก | ใช้ `curl.exe` แทน `curl` |

## 9. หมายเหตุด้านความปลอดภัย

- รหัสผ่าน `Admin123!` ใช้ลองบนเครื่องตัวเองเท่านั้น ถ้าติดตั้งจริง ให้ตั้งรหัสใหม่ที่ยาวและเดายาก แล้วเปลี่ยนตอนล็อกอินครั้งแรก
- ถ้าจะเปิดให้คนอื่นเข้าผ่านอินเทอร์เน็ต ให้ใช้ชุด production ตาม `docs/DEPLOY.md` (มี HTTPS)
- ข้อมูลลูกค้าจริงต้องรอการอนุมัติ PDPA ตาม `docs/PDPA_SUMMARY.md`
