# LeadLoop: คู่มือเดโมและอัปเดตความคืบหน้า (ศุกร์ 30 ต.ค. 2569)

ข้อมูลทั้งหมดเป็นข้อมูลจำลอง ไม่มีข้อมูลลูกค้าจริงและไม่มี API key ในสไลด์/หน้าจอที่แชร์

## วิธีให้พี่เลี้ยง "ดู" และ "ลอง"

ตอนนี้ API รันบนเครื่องเราเท่านั้น (ยังไม่มีหน้าเว็บ/โดเมน) จึงมี 2 ทางที่ทำได้ทันที
1. **แชร์หน้าจอ (ใช้เป็นหลัก):** เราเป็นคนกดให้ดู โดยใช้ Postman collection (`postman/LeadLoop-Leads.postman_collection.json`) และ PowerShell
2. **ให้พี่ลองเอง (ถ้าต้องการ):** ส่ง Postman collection + `docs/LEADS_API.md` ให้พี่รันบนเครื่องพี่เองด้วย `docker compose up --build` (ต้องมี Docker และไฟล์ `.env` ที่ตั้งค่าเอง ห้ามส่ง `.env` ของเรา) หรือรอ deploy บนโดเมนทดลอง (ทำพร้อมหน้าเว็บ ช่วง พ.ย.)

## เตรียมก่อนเดโม (30 นาที ทำคืนก่อนหรือเช้าวันศุกร์)

    docker compose up -d --build
    docker compose restart api                      # ล้างลิมิตล็อกอิน
    $env:SMOKE_ADMIN_PASSWORD = Read-Host "admin password"   # หรือพิมพ์ตอนสคริปต์ถาม
    .\scripts\smoke-test.ps1                        # ต้อง 66 ผ่าน
    .\scripts\leads-smoke-test.ps1                  # ต้อง 13 ผ่าน
    .\scripts\demo-seed.ps1                         # สร้างลีด Cold / Warm / Hot สำหรับโชว์

- รัน `docker compose restart api` อีกครั้งก่อนเดโมจริง (smoke test ล็อกอินผิดโดยตั้งใจ)
- เปิด Postman, ล็อกอิน admin, เก็บ token ไว้ล่วงหน้า ปิดแท็บที่มีรหัสผ่าน/`.env`
- เตรียมแผนสำรอง: ถ้า Gemini ช้า/ล่ม ระบบตกไปใช้เทมเพลตเอง (ถือเป็นจุดที่ดีที่ได้โชว์)

## ลำดับเดโม (ประมาณ 8 นาที)

| # | โชว์อะไร | ทำอย่างไร | พูดว่า |
|---|---|---|---|
| 1 | ระบบรันอยู่ | `docker compose ps`, `GET /health` | API, PostgreSQL, Redis รันด้วย Docker Compose |
| 2 | ล็อกอินและสิทธิ์ | เรียก `GET /campaigns` ไม่มี token (401) แล้วมี token; sales สร้างแคมเปญ (403) | 3 บทบาท admin / marketing / sales ตรวจสิทธิ์ทุกคำขอ |
| 3 | AI วางแผนและสร้างข้อความ | `POST /campaigns/:id/plan`, `/generate-contents` ดูฟิลด์ `generated_by` | AI สำรองสามชั้น Claude, Gemini, เทมเพลต (ตอนนี้ใช้ Gemini ฟรีกับข้อมูลจำลอง) ระบบไม่ล้ม |
| 4 | อนุมัติโดยคน | ส่งอนุมัติด้วยคนสร้างเอง (403) แล้วให้อีกคนอนุมัติ (200) | กฎบริษัท: ผู้อนุมัติต้องไม่ใช่ผู้สร้าง ทุกอย่างลง audit log |
| 5 | ลีดและความยินยอม (PDPA) | `POST /leads` ไม่ส่ง consent (400), ส่ง consent (201) | ไม่มี consent ไม่เก็บข้อมูล |
| 6 | ให้คะแนนด้วยกฎ | `GET /leads` ดู Cold/Warm/Hot; `GET /leads/:id` ดู `score_breakdown` | ให้คะแนนด้วยกฎ อธิบายได้ว่าได้คะแนนเพราะอะไร ไม่ให้ AI ตัดสิน (ถูกกว่าและตรวจสอบได้) |
| 7 | **แก้กฎได้เอง (ที่พี่ขอ)** | `POST /scoring-rules` เพิ่มกฎ, `PATCH` แก้คะแนน, `DELETE`; `POST /scoring-rules/test` ลองก่อนบันทึก; `POST /scoring-rules/recalculate` | เพิ่ม/แก้/ลบ/ปิดกฎได้ ไม่ต้อง deploy ใหม่ กฎหลัก 4 ข้อของพี่ลบไม่ได้ |
| 8 | ส่งต่อทีมขาย | ลีด Hot เป็น qualified, sales เปลี่ยนสถานะเป็น handed_off | ขอคุยกับเจ้าหน้าที่ / ให้ติดต่อกลับ ส่งต่อทันที |
| 9 | สิทธิ์ของลูกค้า | `POST /leads/:id/consent` ถอน consent แล้วส่งข้อความ (409); `DELETE /leads/:id` | ถอนความยินยอมและลบ (anonymize) ได้ตาม PDPA |
| 10 | ทดสอบอัตโนมัติ | โชว์ผล 66 + 13 รายการผ่าน | ทดสอบครบทั้งชุดด้วยสคริปต์เดียว |

ถ้าเวลาเหลือน้อย ให้ทำข้อ 2, 5, 6, 7 ก่อน (สิ่งที่พี่เพิ่งขอ)

## สไลด์อัปเดตความคืบหน้า (4 หน้า)

1. **ทำเสร็จแล้ว:** Backend ครบ (ล็อกอิน/สิทธิ์, AI สำรองสามชั้น, อนุมัติ, audit log, ลีด + consent, กฎคะแนนที่แก้ได้เอง), ทดสอบอัตโนมัติ 79 รายการ, เอกสาร API + Postman, ประมาณการค่าใช้จ่าย
2. **เดโม:** ภาพหน้าจอหรือแชร์สดตามตารางด้านบน
3. **ที่เหลือ/ความเสี่ยง:** หน้าเว็บ (React) ยังไม่เริ่ม, LINE ต้องสร้าง OA เอง (ทำช่องทางจำลองก่อน), deploy + HTTPS, ข้อมูลจริงต้องรอ Deputy Manager อนุมัติตาม PDPA, ตัวเลขคะแนน/เกณฑ์ 50 เป็นค่าเริ่มต้นรอพี่ตรวจ
4. **แผนต่อไป:** ตามกรอบ (ฟีเจอร์ครบ 4 ม.ค.): หน้าเว็บขั้นต่ำ (ล็อกอิน, แคมเปญ, อนุมัติ, ลีด, แก้กฎ) -> LINE ทดสอบ -> job รายวัน -> deploy

## คำถามที่พี่น่าจะถาม

- **ทำไมไม่ให้ AI ให้คะแนนลีด?** กฎอธิบายได้และแก้ได้ ไม่เสียค่า token ต่อลีด ตรวจสอบย้อนหลังได้ (`lead_score_log`) AI ใช้ช่วยเขียนข้อความ/วางแผน ไม่ใช่ตัดสินคะแนน
- **ข้อมูลลูกค้าไปที่ไหน?** เก็บในฐานข้อมูลของเรา ตอนนี้เป็นข้อมูลจำลองทั้งหมด ถ้าใช้ AI ฟรีของ Google ข้อความอาจถูกนำไปปรับปรุงผลิตภัณฑ์ ข้อมูลจริงจึงต้องใช้แบบจ่ายเงินและต้องได้รับอนุมัติตาม PDPA ก่อน
- **ถ้า AI ล่มหรือเกินโควตาจะเป็นอย่างไร?** ตกไปใช้ตัวสำรอง แล้วเทมเพลต และเข้าคิว Redis ลองใหม่ ผู้ใช้ไม่เห็นข้อผิดพลาด
- **คนในทีมเปลี่ยนกฎแล้วลีดเก่าเปลี่ยนไหม?** ไม่เปลี่ยนอัตโนมัติ ต้องสั่งคำนวณใหม่ (admin) เพื่อไม่ให้คะแนนขยับโดยไม่ตั้งใจ
- **พร้อมใช้งานเมื่อไหร่?** Backend พร้อมใช้งานทดสอบแล้ว ส่วนที่ผู้ใช้ทั่วไปใช้ได้จริงต้องมีหน้าเว็บ + deploy ตามแผนข้อ 4 ฟีเจอร์ครบ 4 ม.ค. ไม่ควรรับปากวันที่ที่ไม่ได้อยู่ในแผน
- **ค่าใช้จ่าย?** ดูตาราง Excel ที่ส่งไปแล้ว (ปรับจำนวนผู้ใช้/ครั้งต่อวัน/token ได้)
